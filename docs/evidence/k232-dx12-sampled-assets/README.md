# Sampled-only DX12 asset allocation experiment

Source-only candidate on `codex/k232-dx12-sampled-assets`, based on preserved PR34 carrier `b78f965cc905cc14697969c52ed02332eef934cf`. Its base product tree equals merged master `aa0a6fdbd9f7ee8cde74fd299fe761cfe05beea9`. No Cargo or native command has been executed for this candidate.

Actual PR34 Genuine18 / 01 Editor capture attributed 388.6010 ms to texture creation inside 410.6553 ms inclusive asset upload, with 1238 creations and 1237 evictions. This experiment targets creation cost, not the allocation count or cache capacity. The existing generic resource helper gives sampled assets render-target flags and an optimized clear value even though asset uses are upload/copy and shader sampling. Microsoft advises avoiding that capability for textures that are never rendered to; its [resource-flags documentation](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ne-d3d12-d3d12_resource_flags) also notes possible extra adapter memory. The official [texture-upload example](https://learn.microsoft.com/en-us/windows/win32/direct3d12/upload-and-readback-of-texture-data) creates the copied texture without an optimized clear value. These sources support the API usage, not a promised performance improvement.

`resources::asset_texture` now selects sampled-only capability through the shared existing committed-resource allocator. RGBA8, dimensions, one mip/sample, default heap and COPY_DEST initial state remain identical. The existing upload transitions to pixel-shader resource, row packing/premultiplication, SRV format, sampling and alpha behavior are unchanged. Existing color/depth targets retain their flags and clear values through the same allocator. No heap pool, aliasing, resource reuse, queue/fence change, cache-charge reduction or capacity increase is introduced; charged assets remain `max(data.len(), 64 KiB)` under the existing 64 MiB policy. Profile timer/count meanings remain unchanged.

Stable cached image/gradient IDs and cached shaped-text results can reuse GPU entries. Rendered text shape misses create fresh IDs (`canvas/text.rs`), so the measured GPU misses/evictions do not prove all recreated resources had identical prior keys. The bounded 256-entry/8 MiB shaped LRU includes metrics and rendered entries. A larger GPU cache would not necessarily solve fresh-key churn. Existing evicted assets enter the current frame's retired-resource bucket, cleared only after that frame index's fence wait. Readback submissions use the same command queue and final frame signal; this experiment preserves those lifetimes.

Two targeted descriptor-contract tests cover sampled resource dimensions/copy-sampling format/capabilities/clear absence and compatibility of existing color/depth target formats, sample counts and clear values. They do not execute a D3D12 device, establish pixel lifetime or measure speed. Static rustfmt/diff checks and physical-line counts are the only executed checks at this checkpoint. Stable rustfmt emits the repository's existing nightly-setting warnings.
