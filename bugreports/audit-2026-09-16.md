## Fix priorities and code evidence

1. **App lifetime/identity.** [Ctx](../crates/lurq/src/app/ctx.rs) stores `Option<NonNull<App>>` (line 1019); `app_ref` / `app_ref_mut` dereference it without a lifetime guard (2197–2208). [Tree](../crates/lurq/src/app/runtime.rs) can render from `tick_timers_at` without receiving App (1119–1125), and `pass_inner` skips pointer refresh when a frame is unnecessary (1888–1914). The diagnostic observed `render == old_address` and `render != live_address`. `tests/support.rs::run_pass` also creates an App that dies on return. Treat this as an API soundness issue; documenting or refreshing only inside required passes does not fix it.
2. **MCP/DevTools masking.** [MCP tools](../crates/lurq/src/mcp/tools.rs) use `state.value()` in `node_value_summary` (241), raw node text in `snapshot_node` (311) and an unredacted set-value reply (1094). [DevTools snapshots](../crates/lurq/src/app/devtools/snapshot.rs) copy raw text (230, 312). The public TextInputHandle has no mask query. Fix all output paths together; use synthetic values in regression fixtures.
3. **WGPU multi-instance crash.** [WgpuRenderEngine::new](../crates/lurq/src/app/wgpu_render/mod.rs) still sets `Backends::all()` (385) and creates a separate instance (391). This confirms the reported configuration is unchanged, not that the driver crash was reproduced today. Validate backend selection/instance-lifetime changes with concurrent native surfaces and sequential controls.
4. **Focus reconciliation.** [Tree](../crates/lurq/src/app/runtime.rs) clears missing focus IDs without dispatching blur (5907–5943, 5969–5983); Tab does not fall back to a new form when a stale focused path resolves outside one (3087–3100). [Node identity preservation](../crates/lurq/src/node/node.rs) uses positional pairing for unkeyed children (3787 onward), and [IdGenerator](../crates/lurq/src/core/id_gen.rs) reuses freed IDs without a generation. Existing Tree interaction handles can focus; the missing API is a request available from component Ctx/retained element refs.
5. **Canvas cache behavior.** [MeshCache](../crates/lurq/src/canvas/gpu/cache.rs) evicts FIFO (81–92). Repeated ordered scans over more cacheable keys than capacity can thrash. Keep this separate from the already-resolved absence of cross-frame mesh reuse.

## Corrections to the cache-ceiling report

- `vertices × 8` counts triangle-position payload, **not the cache's complete charge**. Insertion adds `Geometry::bytes()` and 256 bytes per entry. The cited payload sizes alone cannot establish that the entry cap, rather than the byte cap, caused a particular measured threshold. Instrument actual eviction reasons to settle that claim.
- Curveless geometry uses one tolerance key across zoom levels; it does not bypass cache limits. More than 32,768 distinct rectangle geometries, or sufficient byte charge, can still exceed the cache. The report's “however large” statement is only defensible under the consumer's separate 10,000-node cap and other stated assumptions.
- `uploaded_bytes` counts image-source upload bytes, and `vertices` counts prepared output on both hits and misses. Neither measures tessellation misses. The request for explicit counters remains valid.

```powershell
cargo +1.95.0 test -p lurq --locked --features canvas,tokio,form,mcp,devtools,winit --test input_tests mask

```

Results: **173 + 6 + 9 = 188 existing tests passed**, one CPU benchmark intentionally ignored. Existing unused/dead-code warnings were emitted.

Three temporary characterization probes additionally confirmed the App-address, focus-insertion and DevTools-masking defects. These probes assert the defective behavior and are not fixed-behavior regression tests. Their source is retained locally at [target/bugreport-audit-2026-09-16/bugreport_audit_probe.rs](../target/bugreport-audit-2026-09-16/bugreport_audit_probe.rs), outside automatic test discovery. They were run as a temporary `crates/lurq/tests/bugreport_audit_probe.rs` target with the same features and `-- --nocapture --test-threads=1`.

Limits: no fresh concurrent native WGPU run, macOS run, GPU pixel comparison, Canvas performance measurement or route-change focus reproduction. MCP redaction was checked in source; the fresh output probe exercised DevTools directly, without starting an MCP server.
